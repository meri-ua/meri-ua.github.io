# Перевірка зміни на 375×812

Доводить, що зміна працює **в програмі**, а не лише збирається.
Для змін, яких не видно на екрані (tools/, документація), вистачає `npm run check`.

## Кроки

1. **Збірка й доказ:**
   ```bash
   npm run map && npm run check     # має закінчитись «Все гаразд.»
   ```
   Інакше — зупинись і покажи вивід.
2. **Прев'ю:** `preview_start` з конфігом `meri` (`.claude/launch.json`: збирає і
   роздає `dist/` на порту 4174, `autoPort`). Після нової збірки — перезавантажити сторінку.
3. **Розмір:** `resize_window` → `mobile` (375×812), перезавантажити.
4. **Клік саме по зміненому** — по-справжньому (`computer` / `find` + `ref`).
   Щоб швидко дістатись екрана: `?tab=coins`, `?open=<id серіалу>`, `?v=ios|music|glass`.
5. **Консоль:** `read_console_messages` з `onlyErrors`. Помилки = провал.
6. **Перекриття:** `document.elementFromPoint` у центрі й по краях зміненої кнопки
   має повертати саму кнопку, а не плаваючий таб-бар (`.tabbar`) чи аркуш (`.sheet`).
7. **Низ сторінки:** прокрутити донизу; `bottom` останнього блоку ≤ `top` у `.tabbar`.
8. **Теми:** зміна в CSS — знімок у світлій і темній (`resize_window` + `colorScheme`).
9. **Знімок екрана** — показати.
10. **Прибрати:** `resize_window` → `desktop`.

## Звіт

Команда і підсумок `npm run check`, що натиснуто, консоль (N помилок),
`elementFromPoint`, знімок. Чесно — що **не** перевірено (справжній iPhone, інші варіанти дизайну).
